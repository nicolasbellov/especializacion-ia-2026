# Solicitud de cambio o reprogramación
EJEMPLO FICTICIO. Ante una solicitud de cambiar una cita, el agente debe diferenciar una pregunta informativa de una instrucción transaccional. Para mostrar alternativas haría falta verificar identidad, titularidad de la reserva y disponibilidad actual a través del backend autorizado. Después de presentar opciones, cualquier operación de modificación requeriría una confirmación válida del usuario y una respuesta exitosa de la API transaccional. Ningún fragmento de RAG representa una autorización para mover la cita. Mientras la integración no exista, la respuesta honesta es que el asistente académico solo puede explicar el flujo simulado, no gestionar reservas reales.
